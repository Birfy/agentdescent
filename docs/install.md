  <section class="qs-flow"><div><div class="section-label">WHAT HAPPENS IN THE AGENT</div><h2>You stay in control.</h2><p>The agent uses the AgentDescent skill and MCP tools to prepare, run and inspect an evolution. Your real files change only after you approve applying the result.</p><p>Real model-backed runs need a configured provider key; <code>agentdescent doctor</code> reports what is missing. The offline demo below needs none.</p></div><div class="flow-list"><div><span>01</span><b>Doctor + plan</b><small>Checks setup, validates cases and quotes the call count.</small></div><div><span>02</span><b>Start + status</b><small>Runs in the background and reports progress.</small></div><div><span>03</span><b>Show + apply</b><small>Displays the diff; application is a separate approval.</small></div></div></section>

  <section class="qs-technical"><details id="source-checkout"><summary>Before publication, or developing from source</summary><p>Clone the repository and install the MCP extra from your checkout. The Python package supports Python 3.9+; MCP tools need Python 3.10+. NumPy is installed for prediction-powered auditing.</p><pre>git clone --branch main https://github.com/Birfy/agentdescent
cd agentdescent
pip install -e ".[mcp]"</pre></details><details id="source-examples"><summary>Run the source-only research examples</summary><p>Research examples are outside the wheel. After 0.5.1 is published, clone its matching tag and install the development extra:</p><pre>git clone --branch v0.5.1 https://github.com/Birfy/agentdescent
cd agentdescent
pip install -e ".[dev]"
python -m examples.run_demo</pre><p>The tag is created at publication. Before then, use your release-candidate checkout with <code>pip install -e ".[dev]"</code>. See <a href="../usage/">run everything</a> for the remaining examples.</p></details><details id="building-the-docs"><summary>Building these docs locally</summary><p>From the repository checkout, run <code>pip install -e ".[docs]"</code>, then <code>mkdocs serve</code> for a local preview or <code>mkdocs build --strict</code> for the production build.</p></details></section>
